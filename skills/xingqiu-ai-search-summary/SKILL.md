# 星球AI搜索总结

用户已经在该星球内搜索。先判断输入，只走一个接口。每页最多 20 条。同一搜索词继续挖掘时用已打分列表，不要重新请求。

## 判断输入

不算星球名。

- 一段话：有句号、问号或感叹号，或是在陈述、提问一件事的完整句子。调用 `search_topics`（参数只有 `group_id`、`query`，没有翻页参数）。
- 多个关键词：用空格、逗号、顿号、加号或斜杠分开，读起来不是一句完整的话。调用 `call_zsxq_api`。
- 单个关键词：其余一个连续的词或短语。调用 `call_zsxq_api`。

不要两个接口一起查，结果不足时也不要改走另一个。`search_groups`、`search_group_members`、主题详情、评论、标签、发帖、笔记都不用。`group_id` 和 `topic_id` 保持字符串。两个接口都不返回相关度，分数由本次总结打。`search_topics` 用 `topics_brief`，另有 `count`、`has_more`、`success`、`error`。`has_more` 为 true 也不要再调。

## 步骤

1. 读取本次 `group_id` 和搜索内容。缺哪项只追问哪项，不要猜星球。
2. 没换搜索词，只是继续看、换一批、不满意或继续挖掘：不请求接口。跳过已展示的 `topic_id`，再输出最多 20 条。
3. 换了搜索词、确认了某个候选词，或该词第一次总结：丢掉上一份打分，按新词重新判断并请求。确认后的词按它自己的类型选接口。
4. 一段话。`query` 用整段输入，不拼星球名。`success` 为 false 时原样输出 `error` 后停止。常见原文是「该星球暂未开通 Skill 权限，如需使用，可联系星主申请开通。」只给 `group.group_id` 与本次星球一致的条目打分。首页只展示大于 80 分的，从高到低，最多 20 条。没有时按「可能的正确词」最多给 3 个，没有候选就不要猜。
5. 关键词。`GET /v2/search/groups/{group_id}/topics`。`keyword` 保持用户原分隔，`count` 为 20，`order_by` 为 `default`。第一页不传 `index`，下一页用上一页 `resp_data.index`。不传 `filter_roles`、`filter_types`，不拼星球名。正文用 `talk.text`，没有则用 `question.text` 与 `answer.text`。`topic_id`、`owner.name`、`owner.user_id` 原样拷贝。链接的 `group_id` 用本次星球 ID。本页少于 20 条、本页为空，或返回的 `index` 与请求的相同，就停止。全部取回后一次打分。首页只展示 90 分及以上，从高到低，最多 20 条，不用 89 分及以下凑满。没有 90 分及以上时，按「可能的正确词」最多给 3 个，没有候选就不要猜。
6. 把搜索词、输入类型、接口、每条的 `topic_id`、分数、用户名、`user_id`、`group_id`、摘要，以及已展示的 `topic_id` 留在对话里。
7. 继续挖掘仍从高到低，每页最多 20 条。一段话只继续展示未展示且大于 80 分的。关键词先展示未展示的 90 分及以上，再展示 81 到 89 分。该档已完时不重复，写「相关主题已经展示完。可补充关键词，或去搜索结果里看看。」

## 无法展示的内容

返回里没有高风险、用户自己删除、发布者被拉黑、限制搜索词的分类和数量，不要汇总或猜测。`intercepted_count` 只是合计数，不带原因，不要把它说成上述任何一类。只有 `error` 或字段原文写明原因时，才转述该原文。

## 可能的正确词

只在关键词首页没有 90 分及以上，或一段话没有大于 80 分的主题时考虑。

候选必须是本次正文里连续出现过的实际用词，至少 2 个字；英文至少 2 个字母。一个字的不推荐。不能编造正文里没有的词，也不要按社区内容方向另猜。

比较对象：关键词用用户输入。一段话不用整句，用句中要找的名称，例如「好像叫做花布」里的「花布」。原词已连续出现时不给候选。不限只差一个字，差两个字也可以，只要这个词就是用户要找的名称。读音、字形或用词对得上即可。同音含同音节、声调不同。例如「奥云回」可推荐正文里的「奥运会」；「花布」推荐「星球数据画布」，不要拆成「花」或「布」。多个关键词只替换对不上、且正文里有实际用词的那一段，分隔符不变。

最多 3 个。更像目标名称的靠前；同样像的，出现条数多的靠前。不足 3 个不凑。没有候选就不写。

每个词单独链接，`keyword` 用 UTF-8 百分号编码，与链接文字解码后相同。多个用顿号隔开：

`可能是指 [候选词](zsxq-skill://xingqiu-ai-search-summary?keyword=百分号编码)、[候选词](zsxq-skill://xingqiu-ai-search-summary?keyword=百分号编码)`

客户端把以 `zsxq-skill://xingqiu-ai-search-summary?keyword=` 开头的链接当点击事件：取出被点的 `keyword`，解码后用当前星球重新调用本技能。不要写成普通网页链接。点击或确认其中一个之前不要改词、不要再请求，也不要一次搜多个。

## 置信度

总分 100 的整数。只看清理后的正文和关键词，不看点赞、评论、阅读、精华或接口顺序。

- 90–100：正文就是在讨论这件事。整篇在谈它时，即使没有逐字写出关键词，也归这一档。
- 81–89：正文明确用该关键词讲了一件事，但不是整篇主题。
- 80 及以下：字形、读音或缩写接近，或没有实质讨论。只出现在链接或转发标题里，或只是清单、模板、会议名称里的一个字眼，也归这一档。

80 分不进入总结。一段话首页最低 81 分。关键词首页最低 90 分。

## 读一条主题

摘要不超过 50 个字，不含序号、用户名、「查看」和链接。`search_topics` 用 `content`。关键词搜索用上面的正文。`title` 只在已是完整短句时借用。超过就删到 50 字以内，留和关键词最相关的事实。用户名用 `owner.name`，链到 `https://wx.zsxq.com/dweb2/index/footprint/{user_id}`，`user_id` 用 `owner.user_id`。没有名字不写用户名；没有 `user_id` 只写名字。不展示头像。「查看」链到 `https://wx.zsxq.com/group/{group_id}/topic/{topic_id}`。一段话的 `group_id` 用该条 `group.group_id`，关键词搜索用本次星球 ID。`topic_id` 原样拷贝。打分前先清理：`<e>` 的 `href`、`title` 百分号解码后只取标题或标签；重复段落留一份；不描述图片和文件，不声称读过。

## 输出

用中文，不写分数。每句对得上该条正文，不补充星球里没有的信息。序号写成 `1. `（半角点号加空格）。`xx` 是用户输入，`y` 是本次打分条数，`z` 是本页门槛以上的条数。`z` 大于 20 时开头仍写实际 `z`，列表只留最高 20 条。本页没有合格主题时不输出列表。

一段话没有合格主题：「主题正文里没有读到在讨论这件事。可补充一个记得的原话、作者或大概时间。」关键词连 81 分都没有：「没有找到。试试用一段话描述下你要找的内容，或补充一个记得的原话、作者或大概时间...」关键词仍有 81 到 89 分：「感觉结果不太对？试试用一段话描述下你要找的内容，或补充一个记得的原话、作者或大概时间...」有候选词时，把「可能是指」那句接在说明后面。

```markdown
”xx“在本星球里找到 y 条内容，其中关联度最高的 top z 是：
1. [{用户名}](https://wx.zsxq.com/dweb2/index/footprint/{user_id})： {这一条在说什么} - [查看](https://wx.zsxq.com/group/{group_id}/topic/{topic_id})

如没找到你想要的，可尝试继续补充关键词，或去搜索结果里看看。
```

继续挖掘且还有未展示主题时，不重复「找到 y 条」，序号接着排，每页最多 20 条，底部仍用上面这句。
