# 回答知识星球产品文档问题（answer-product-docs）

用户问知识星球的**产品功能、规则、常见问题**时，读官方帮助中心 doc.zsxq.com 的 markdown 版本后回答。本场景是 zsxq skill 的**只读知识问答**分支：不调用 zsxq-cli，不操作星球内容，不查星球数据——那些由 zsxq 的其它场景/原子操作负责，二者互补不重叠。

**核心约束：只答帮助中心里有的内容。文档没写的，明说没写，不用模型知识补充。**

## 适用意图

问题主体是「知识星球这个产品」，答案应当有官方口径：

- 功能怎么用（发布、设置、权限、后台操作路径的**规则说明**，非代为操作）
- 规则与政策（退款条件、费率、提现、企业认证、协议条款）
- 报错与异常现象（打不开、收不到、审核不通过是什么原因）
- 角色差异（星主能做什么 / 普通成员能做什么）
- 平台公告涉及的变更

触发语示例：「星球怎么退款 / 退款要多久 / 手续费多少 / 费率是多少 / 提现多久到账 / 怎么开发票 / 企业认证要什么材料 / 分享有赏比例 / 为什么审核不通过 / 违规封禁规则 / 用户协议怎么说」。

## 不适用情况

以下**不在本场景处理**，交回 zsxq 主路由的对应场景/操作，不要在本场景臆造操作步骤或直接拒绝：

| 请求类型 | 说明 | 去向 |
|---------|------|------|
| 操作星球内容 | 发帖、加精、改标签、改设置、删除 | 主路由 → topic-create / topic-set / topic-tags / group-settings 等 |
| 查询星球数据 | 成员数、活跃度、收入明细、到期时间 | 主路由 → group-list / group-members / 巡场等 |
| 生成运营素材 | 写文案、做海报、生成小刊、剪辑视频 | 主路由 → 对应生成场景 |
| 个案 / 账号状态 | 「我的退款为什么没到」「我的星球为什么被封」 | 说明通用规则（若文档有）后引导官方客服，不下个案结论 |
| 非知识星球产品 | 通用问题 | 直接回答，不进本流程 |

用户在得到产品规则答复后**追加操作意图**（如「那帮我退了」），同样交回主路由。

## 所需输入

用户的自然语言产品提问。无需 group_id / topic_id 等 ID——本场景不触达任何星球对象。

## 使用的原子操作

**本场景不调用 zsxq-cli。** 仅对外部文档站做只读 WebFetch：

1. 读索引 `https://doc.zsxq.com/llms.txt` 定位相关文档
2. 读命中文档的 `.md` 版本获取正文

检索机制、URL 约定、栏目映射见 [doc-index](answer-product-docs/doc-index.md)。

## 执行流程

1. **边界判断** — 确认属于产品使用/规则类提问；否则按「不适用情况」交回主路由或直接回答。见 [answer-policy](answer-product-docs/answer-policy.md) 第一节。
2. **检索文档** — WebFetch `llms.txt`，先扫「核心栏目」「重点文档」，未命中再扫「全部栏目文档」，按栏目+标题关键词选 **1–3 篇**最相关的，WebFetch 其 `.md` 读正文。见 [doc-index](answer-product-docs/doc-index.md) 检索流程。
3. **组织回答** — 结论先行，50–600 字，术语用文档原词，数字逐字照搬（费率/期限/比例/金额不换算），底部标注来源（用 `.html` 地址）。见 [answer-policy](answer-product-docs/answer-policy.md) 第三、四节。

## 分支与停止条件

- **文档只覆盖一部分** → 答已有部分，明确划出边界，不推测补齐（[answer-policy](answer-product-docs/answer-policy.md) 情况 B）
- **文档完全没收录** → 直说未收录 → 给最接近的相邻文档 → 引导官方客服，不编造、不臆造链接（情况 C）
- **多篇说法不一致 / 疑似过期** → 按 frontmatter `updated` 取最新，提示以页面最新正文为准，不自行裁定谁更合理（情况 D）。费率/公告/协议类同题多版尤其要回索引比对 `updated`。
- **索引或正文拉取失败** → 直说无法访问帮助中心，不凭记忆作答、不猜 slug 拼 URL，引导稍后重试或联系客服。此条优先于「先给答案」。
- **属于个案 / 账号状态** → 停在通用规则，指向官方客服。

## 用户确认点

无写入操作，无需执行前确认。唯一需向用户澄清的情形：提问过于笼统、无法定位到具体文档时，先问清指向（如「退款」是想问条件、时效还是入口）再检索。

## 完成标准

- 回答内容全部可追溯到帮助中心正文，无模型知识补充、无推断措辞（「应该」「一般来说」）
- 费率、期限、比例、金额等数字与文档逐字一致，未换算改写
- 术语用文档原词（星主 / 星球 / 主题 / 成员），未换同义词
- 底部按固定格式标注来源，链接用 `.html`；未收录情形也标注「帮助中心未收录」+ 相邻文档
- 操作 / 数据 / 个案类请求已正确交回主路由或引导客服，未在本场景臆造

## 失败与回退

- 命中文档读不出答案：回索引换关键词重新定位，而非无限加篇数（上限 1–3 篇）
- 索引不可达：见「分支与停止条件」，宁可不答也不编
- 误判边界（把操作类当问答）：发现后立即交回主路由，不继续在本场景推进
