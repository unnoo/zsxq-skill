# 使用 Skill Pay 完成知识星球购买（purchase-with-skill-pay）

将用户的付费加入、续期、购买礼品卡/轻读、付费提问或赞赏意图，编排为“核对订单 → 创建订单 → 宿主展示微信支付卡片 → 由知识星球原支付链路履约”的流程。

## 适用意图

- 「付费加入这个星球」「帮我续费这个星球」
- 「购买礼品卡 / 轻读 / 创建星球邀请码」
- 「向这个用户付费提问」「赞赏这个用户 / 主题 / 评论」
- 「用 Skill Pay / 微信支付完成这笔知识星球订单」

## 不适用情况

- 当前宿主不是 WorkBuddy（包括 Claude Code / CC 等其他 Agent 环境）→ 说明 Skill Pay 仅支持 WorkBuddy，要求用户切换后重新发起；不得创建订单
- 用户只想查询价格、资格或订单状态，不准备创建订单 → 不创建订单；当前工具也没有支付查单能力
- 用户要求 agent 自动确认付款、跳过支付授权或代替用户完成财务确认 → 拒绝该部分请求

## 所需输入

- 订单类型及业务含义
- 与类型对应的目标 ID；赞赏评论需要 `topic_id` 和 `comment_id`，轻读需要 `group_id` 和 `back_issue_id`
- 按订单类型查询或计算出的应付金额
- 需要用户定价时，由用户指定的金额
- 按需提供：优惠券码、验证信息

| 操作 | reference | 在本场景中的作用 |

| 创建微信订单 | [wechat-order-create](../wechat-order-create.md) | 创建订单、解释 402 支付挑战及安全恢复 |
| 列出/搜索星球 | [group-list](../group-list.md) | 付费加入、续期等场景核对 `group_id` 和星球名称 |

| 搜索星球成员 | [SKILL.md 星球 API 表](../../SKILL.md#星球管理group) | 付费提问/赞赏用户时核对 `user_id` 与昵称 |

## 执行流程

进入流程前先确认当前宿主是 WorkBuddy 且提供官方 `weixinpay_pay`。任一条件不满足时，在创建订单前说明限制并停止。

### 第一步：确认购买意图

把用户意图映射为 [wechat-order-create](../wechat-order-create.md) 中的订单类型。语义不唯一时列出候选让用户选择，例如“支持作者”可能是 `reward_user` 或 `reward_topic`。

### 第二步：核对对象和订单参数

使用只读操作核对目标名称/内容及 ID，并只保留该订单类型必要的字段。

完整执行 [wechat-order-create：下单前查询价格](../wechat-order-create.md#下单前查询价格)；需要用户定价时，同时执行其[金额换算规则](../wechat-order-create.md#金额换算规则)。字段路径、价格公式、固定价格不可改写及停止规则均以该原子 reference 为准，本场景不另行定义。

赞赏评论时，若只有 `comment_id` 而没有所属 `topic_id`，停止并请用户补充主题；取得两者后再用 `get_topic_comments` 核对。轻读只有链接或 `back_issue_id`、无法可靠取得所属 `group_id` 时同样停止并请用户补充，不得猜测。

### 第三步：创建订单前确认

向用户展示一份紧凑订单摘要：类型、对象、金额及必要字段。明确说明“这一步会创建真实待支付订单；随后微信支付卡片仍需你本人确认”。取得明确同意后，才调用 `call_zsxq_api`。

### 第四步：处理支付挑战

收到 `code == "PAYMENT_REQUIRED"` 且 `status_code == 402` 时，即使响应为 `success: false`，也按 [wechat-order-create：宿主微信支付授权](../wechat-order-create.md#宿主微信支付授权)完整执行支付码冲突、缺失和 `expires_at` 过期检查。将 `out_trade_no` 原样保存为字符串；由用户在官方支付卡片中决定是否支付。

### 第五步：完成或停止

- 用户完成支付：说明订单后续由知识星球原支付回调履约；当前工具无法查单时，不声称支付成功或已履约，可引导用户在知识星球相应页面核对结果。
- 用户取消/拒绝/支付超时：停止，不创建第二张订单。
- `SKILLHUB_PREORDER_FAILED`：按原子 reference 的恢复响应字段与冲突检查进入安全恢复分支。
- 其它失败：按原子 reference 的失败语义停止并报告。

## 分支与停止条件

- **宿主不是 WorkBuddy，或 WorkBuddy 未提供官方 `weixinpay_pay`**：说明当前无法完成 Skill Pay，停止且不得创建订单
- **订单语义不唯一**：列出订单类型候选，等待用户选定
- **对象 ID 不明确/命中多个**：列出候选（ID + 名称/摘要），等待用户选定
- **原子 reference 要求的对象或价格数据缺失**：停止并请求缺失信息；固定价格订单不得由用户提供任意金额替代查询结果
- **订单类型不在支持列表中**：停止并说明当前 Skill Pay 不支持该类型
- **`PAYMENT_REQUIRED`**：交给宿主展示支付卡片；不得再次创建订单
- **`SKILLHUB_PREORDER_FAILED`**：只用签名 token 恢复 SkillHub 预下单；token 无效/过期则停止
- **配置/解析/签名恢复错误**：停止并报告；不得盲目重试创建订单
- **用户取消、拒绝或超时**：停止；只有用户再次明确要求且重新确认订单摘要后，才可考虑新订单
- **无法查询支付状态**：不把支付挑战或口头陈述当作成功，提示用户到知识星球业务页面核对

## 用户确认点

1. **创建订单前**：按原子 reference 确认订单类型、对象、实际应付金额及必要字段
2. **支付授权时**：由宿主展示微信支付卡片，必须由用户本人确认；agent 不代操作
3. **取消/过期后重新下单前**：视为新财务操作，重新展示完整订单摘要并再次确认

## 完成标准

- 已创建唯一订单并把唯一的支付挑战交给支持 Skill Pay 的宿主；或在明确停止条件处安全停止
- `out_trade_no` 原样保存为字符串且未发生重复下单
- 不把 `PAYMENT_REQUIRED` 当作支付成功；支付与履约状态表述符合知识星球原支付链路的实际边界
- 若发生预下单恢复，仅重试 SkillHub 预下单，没有再次发送订单 body

## 失败与回退

- 任何无法判断“订单是否已经创建”的错误都按“可能已创建”处理，禁止直接重放首次请求
- `SKILLHUB_PREORDER_FAILED` 的 `payment_retry_token` 是唯一安全恢复凭据；仅有 `out_trade_no` 不足以恢复
- 当前没有支付查单工具，不能实现官方通用流程中的“支付后携订单号查单履约”；这里由知识星球既有支付回调负责。需要确认结果时，回到知识星球业务页面只读核对
- 支付环境能力缺失（宿主不识别 `WeixinPay` 元数据）时，保留订单号并停止，告知用户需要支持 Skill Pay 的宿主，禁止改用非官方方式收集付款
