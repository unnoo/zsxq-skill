# 整理评论区问题帮星主回复（triage-comments）

批量拉取星球最近若干主题的评论区，按问题类型归类、找出星主尚未回复的评论、为每条生成温和亲切的回复草稿，列成清单交星主逐条确认。**默认只读取、只起草；发评论必须经星主逐条显式确认（说 "OK"）后才执行。**

## 适用意图

- 「帮我查『星球名』最近 5 条主题的评论区，整理问题给我回复」
- 「直播 / 训练营 / 活动后评论太多，帮我归类并起草回复」
- 「找出我还没回复的评论，给我回复草稿，我确认后再发」
- 评论多、星主时间有限，需要先归类、筛未回复、再逐条确认发出

## 不适用情况

- 只想看某一条主题的评论、不需要归类/起草 → 直接用 `api call get_topic_comments`（无独立 reference，见 [SKILL.md 主题 API 表](../../SKILL.md#主题管理topic)）
- 处理别人向你发起的**提问**（q&a 提问箱）而非评论 → 见提问管理场景 / [topic-answer](../topic-answer.md)
- 只是要发一条评论、已想好内容 → 直接用 [topic-reply](../topic-reply.md)
- 想按关键词找内容而非按主题拉评论 → [topic-search](../topic-search.md)

## 所需输入

- **必填**：星球名称或 `group_id`（只给名称时先用 `group +list` 解析）
- 可选：主题数量（默认最近 5 条）、每条主题取多少评论（默认前 20 条）、归类维度（默认：工具使用 / 内容反馈 / 求推荐 / 情绪支持 / 其他）、回复草稿语气与字数（默认温和亲切、100 字以内）
- 前提：操作账户即该星球**星主本人**（当前登录账户，用 `user +info` 取其 `user_id` 作为"星主"判定基准）；若操作者并非星主，本场景"找未回复"的前提不成立

## 使用的原子操作

| 操作 | reference | 在本场景中的作用 |
|------|-----------|-----------------|
| `group +list` | [group-list](../group-list.md) | 星球名 → `group_id`（只给名称时的前置解析） |
| `user +info` | [user-info](../user-info.md) | 取当前登录账户 `user_id`，作为"星主"身份基准，用于判断评论作者与星主的关系 |
| `group +topics` | [group-topics](../group-topics.md) | 拉该星球最近 N 条主题（默认 5） |
| `api call get_topic_comments` | 无独立 reference（在 [SKILL.md 主题 API 表](../../SKILL.md#主题管理topic)登记，参数 `topic_id` / `limit` / `index`） | 逐条主题拉评论（默认前 20 条），得到评论作者、内容、时间 |
| `topic +reply` | [topic-reply](../topic-reply.md) | **写入**：星主逐条确认后发评论 / 楼中楼回复（`--reply-to <comment_id>`） |

## 执行流程

### 第一步：确认星球与星主身份

1. 若用户只给星球名称：用 `group +list` 查到 `group_id`；命中多个相似名称时列出候选（`group_id` + 名称）让用户选，不默认取第一个
2. 用 `user +info` 取当前登录账户的 `user_id` 与 `name`，记为**星主标识**。后续所有身份判断以 `user_id` 为准 —— **不要用昵称判断**（不同账户可能重名，实测见过两个不同 `user_id` 同名"明明"）

### 第二步：拉最近主题

用 `group +topics --group-id <id> --limit <N>`（默认 N=5，最大 30）取最新主题，记录每条的 `topic_id`、标题/摘要、类型。数量不足 N 条时按实际数量继续。

### 第三步：逐条主题拉评论

对每个 `topic_id` 调 `api call get_topic_comments --params '{"topic_id":"<id>","limit":20}'`：

- 返回 `comments` 数组（顶层含 `count` / `has_more` / `index`）；每条评论关键字段：`comment_id`、`owner.user_id`、`owner.name`、`text`、`create_time`、`group_owner_liked` / `topic_owner_liked`
- 只需前 20 条时单页即可；`has_more: true` 且用户要求取更多时，用返回的 `index` 值作为下一页 `index` 参数继续翻页
- 评论为空的主题跳过

### 第四步：归类 + 筛未回复

对每条评论：

1. **归类**：按维度打标签（工具使用 / 内容反馈 / 求推荐 / 情绪支持 / 其他）
2. **判定作者与星主关系**：`owner.user_id == 星主 user_id` 的是星主自己发的（是回复动作，不是待回复对象）；其余为**成员评论**，是候选
3. **筛未回复**（关键，注意接口限制）：`get_topic_comments` 返回**扁平列表，无楼中楼归属字段**（无 `repliee` / 被回复评论 ID），无法从接口直接把"星主的某条回复"对应到"哪条成员评论"。据此采用：
   - 该主题下**完全没有**星主评论 → 该主题全部成员评论标为**未回复**
   - 该主题下**有**星主评论、但无法确定其针对哪条成员评论 → 相关成员评论标为**待确认**，交用户判断，不擅自判为已回复
   - `group_owner_liked` / `topic_owner_liked` 仅作参考信号（星主点过赞），**不等于已回复**

### 第五步：为未回复评论起草

对每条"未回复 / 待确认"评论生成一条回复草稿：语气温和亲切、100 字以内、扣住评论内容与其归类。每条草稿记录：所属主题（`topic_id` + 标题）、原评论（`comment_id` + 作者 + 原文摘要）、归类、草稿正文；楼中楼回复额外标注 `--reply-to <comment_id>`。汇总成清单交用户。

### 第六步：逐条确认后发评论（写入）

按 [topic-reply](../topic-reply.md) 发送：星主对某条说 "OK" 才发那一条，`--reply-to` 指向对应 `comment_id`（楼中楼回复原评论）。未确认的不发。

## 分支与停止条件

- 星球名命中多个 → 列候选让用户选；查不到 → 提示核对名称或改用 `group_id`
- 该星球未开通 Skill 权限（`group +topics` / `get_topic_comments` 报 `该星球暂未开通 Skill 权限`）→ 提示星主在星球设置中申请开通后再跑，不硬试
- 最近主题不足 N 条 → 按实际数量继续
- 某主题评论为空 → 跳过该主题
- 所有成员评论都已被星主回复（无未回复/待确认项）→ 报告"无待回复评论"，结束
- 单主题评论超 20 条 → 默认只取前 20；用户要全部时用 `index` 翻页
- 限流（429 / `frequently`）→ 退避几秒重试，不循环猛刷

## 用户确认点

1. **发每一条评论前逐条确认**：展示【所属主题 + 原评论作者与原文 + 归类 + 回复草稿 + 是否楼中楼】，星主对该条明确说 "OK" 才发该条 —— 不批量群发、不默认全发
2. 星球名命中多个时，选定哪个星球需用户确认
3. "待确认"（无法判定是否已回复）的评论，是否需要回复由用户判断，不擅自发送

## 完成标准

- 已拉取指定星球最近 N 条主题、每条前 M 条评论（默认 5 / 20）
- 每条评论完成归类，成员评论完成"已回复 / 未回复 / 待确认"判定（判定基于 `user_id`）
- 每条未回复评论有一条 ≤100 字、语气温和的草稿，并列成清单交星主确认
- 仅星主逐条确认过的草稿被发出；未确认的未发送

## 失败与回退

- 每条主题、每条回复相互独立：某条 `get_topic_comments` 或 `topic +reply` 失败不影响其他条，从下一条续跑即可
- `topic +reply` 写入失败即原子回滚，不留半成品评论（见 [topic-reply 失败语义](../topic-reply.md#失败语义)）；已成功发出的评论本流程无法撤回，需手动删除
- 部分主题无权限 → 跳过并在清单中标注，其余照常处理
