# 负面内容监控（monitor-risky-content）

定期巡查星主管理的星球，识别新主题和评论中的风险内容（辱骂、人身攻击、广告引流、敏感词、投诉、吐槽负面、用户冲突），按高/中/低分级输出给星主审核。**本场景只读：只发现、只上报，绝不自动删除或处置；任何处置动作都由星主确认后另行执行。**

## 适用意图

- 「检查我管理的『XX』星球过去 24h 的新主题和评论，有没有辱骂 / 广告 / 投诉」
- 「帮我巡查星球风险内容，按高中低分级，给我审核，不要直接删」
- 「每隔 1 小时监控一次星球负面内容」
- 活动 / 大促期间、成员多更新快时的重点巡查，日常降低运营风险

## 不适用情况

- 想让 AI **直接删除 / 禁言 / 处置**风险内容 → 本场景不含处置；星主确认后用 [topic-delete](../topic-delete.md) 等写入操作单独执行
- 一次性找某条内容或按关键词搜 → 用 [topic-search](../topic-search.md)
- 想做正向的内容复盘 / 运营周报（非风险向）→ 用复盘 / 周报类场景
- 巡查的不是本人管理、也无权查看的星球 → 看不到内容则无法监控；本场景定位为星主巡查自己管理的星球

## 所需输入

| 输入 | 必填 | 说明 |
|------|------|------|
| 星球名称或 group_id | 是 | 只给名称时先 `group +list` 查 ID；命中多个候选让用户确认 |
| 时间窗 | 否 | 默认过去 24h；周期巡查时用「上次巡查以来」，见执行流程第一步 |
| 关注的风险类型 | 否 | 默认全部 7 类；用户可缩小（如「只看广告和辱骂」） |
| 巡查频率 | 否 | 默认按用户要求（如每 1 小时）；由 agent 定时能力驱动，见「周期巡查与时间窗」 |

## 使用的原子操作

| 操作 | reference | 在本场景中的作用 |
|------|-----------|-----------------|
| `group +topics` | [../group-topics.md](../group-topics.md) | 拉时间窗内的新主题，用 `--end-time` 控游标翻页 |
| `api call get_topic_comments` | [SKILL.md 主题 API 表](../../SKILL.md#主题管理topic) | 拉主题评论，按 comment 的 create_time 过滤新评论（参数 topic_id / limit / index） |
| `topic +detail` | [../topic-detail.md](../topic-detail.md) | 需要上下文判断冲突 / 攻击，或主题正文被截断时拉完整内容 |
| 分享链接拼接 | [../share-links.md](../share-links.md) | 为每条风险项输出对应主题链接 |

## 执行流程

### 第一步：确定星球与时间窗

1. 星球：直接用 group_id；只给名称时先 `group +list` 定位（命中多个见「分支与停止条件」）
2. 时间窗（起点 → 现在）：
   - **首次巡查**：起点 = 现在往前 24h
   - **周期巡查**：起点 = 上次巡查已处理的最大 create_time（见「周期巡查与时间窗」）

### 第二步：拉时间窗内的新主题

`group +topics --json` 按 create_time 倒序返回。从第一页开始，逐条比对 `create_time`：

- 落在时间窗内 → 收入待判定集合
- 早于时间窗起点 → 停止翻页（后面只会更早）
- 未翻完且 `has_more: true` 时，用返回的 `next_end_time` 作 `--end-time` 继续下一页

### 第三步：拉时间窗内的新评论

风险常出现在评论里，且**旧主题也可能被评论新的风险内容**。候选主题集 =「本次新主题」+「星主指定关注的近期活跃主题」（可选，用户可给一批 topic_id 或让其覆盖最近 N 天主题）。对每个候选主题：

- `api call get_topic_comments`（参数见上表 reference），按每条 comment 的 `create_time` 只保留落在时间窗内的新评论
- 主题 `counts.comments` 为 0 的可跳过，减少无谓调用

> 说明：现有只读能力没有「全站按评论时间排序」的入口，评论只能逐主题拉取。因此评论监控的覆盖面取决于候选主题集；默认覆盖新主题的评论，更旧主题需星主把它们列入关注集。

### 第四步：识别与分级

对每条新主题 / 新评论做语义判断，命中风险类型（辱骂、人身攻击、广告引流、敏感词、投诉、吐槽负面、用户冲突）则按下表分级。判断需要上下文（如楼中楼冲突、正文被截断）时，用 `topic +detail` 拉完整主题再判定。

| 风险等级 | 判定参考 | 典型例子 |
|---------|---------|---------|
| 高 | 明显违规、需尽快处理 | 露骨辱骂 / 人身攻击、带外链或联系方式的广告引流、政治或色情敏感词、激烈用户冲突 |
| 中 | 需星主关注、酌情处理 | 明确投诉与不满、隐性引流（诱导加微信 / 私聊）、指名道姓的负面评价 |
| 低 | 轻度负面 / 疑似误伤 | 一般性吐槽、情绪化但无攻击对象的抱怨、疑似但不确定的广告 |

> 分级依赖语义判断，边界情况倾向**上调一级**或标注「需人工复核」，最终由星主裁定。不要因为「拿不准」而漏报。

### 第五步：输出审核报告

按风险等级（高→低）、同级按时间倒序汇总，每条一行：

| 风险等级 | 类型 | 原文或摘要 | 主题链接 | 风险原因 |
|---------|------|-----------|---------|---------|
| 高 | 评论 | （原文，过长则摘要，标注作者） | （对应主题链接） | 命中的风险类型 + 一句话理由 |

- **原文或摘要**：短内容给原文，长内容给摘要并保留关键片段；评论注明发布者昵称
- **主题链接**：用 [share-links](../share-links.md) 拼接。评论没有独立 URL → 用其所在主题的链接，并在该行标明「评论于此主题」
- 无风险内容时也要明确报告「本次时间窗内未发现风险内容」

## 周期巡查与时间窗

- 「每隔 1 小时巡查」是**周期性任务**，由 agent 的定时能力（cron / 定时触发 / 平台调度）驱动，每小时触发一次本流程；单次触发只跑上面五步。
- **避免重复告警**：用「水位线」= 上次巡查已处理的最大 create_time。下次巡查时间窗起点 = 该水位线，只报增量。主题按 topic_id、评论按 comment_id 再做一次去重，兜住边界时间点的重复。
- **水位线持久化**：由 agent 在自身状态 / 记忆中保存上次水位线；无持久化能力时，回退为固定「过去 24h」窗口，并对与上次结果的重叠部分按 ID 去重（或让用户提供上次时间点）。
- 无法自动调度的平台 → 退化为按需触发：用户每次手动说「巡查一次」，仍按水位线增量。

## 分支与停止条件

- 时间窗内无新主题也无新评论 → 报告「无新增 / 未发现风险」，结束
- 星球名命中多个候选 → 列出 group_id + 名称让用户确认，不默认取第一个
- 内容量很大 → 优先输出高风险项，其余按等级分批；翻页一旦越过时间窗起点即停止
- 命中限流（429 / `frequently`）→ 退避几秒重试，不循环猛刷；仍失败则记为「部分未扫描」（见失败与回退）
- 某主题无权查看 / 已删除（403 / 404）→ 跳过并标注，不中断整体巡查

## 用户确认点

本场景**全程只读，无写入确认点**。核心红线：

- **AI 不自动删除 / 禁言 / 编辑任何内容**，只产出审核报告交星主判断
- 星主看过报告、明确要处置某条时，才转对应写入操作（如 [topic-delete](../topic-delete.md)）并遵守该 reference 的 `> [!CAUTION]` 与 [安全规则](../../SKILL.md#安全规则)

## 完成标准

- 时间窗内的新主题、候选主题的新评论已扫描完（或对未扫完项做了标注）
- 风险项按高/中/低分级，逐条给出「原文或摘要 · 主题链接 · 风险原因」；无风险时明确报告未发现
- 记录本次已处理的最大 create_time 作为下次增量巡查的水位线

## 失败与回退

- 巡查是只读的，中断不会改动星球数据，可直接重跑。
- 部分主题因限流 / 无权限未扫完 → 报告中列出未扫描的主题，**水位线只推进到已完整扫描的范围**，保守留待下次重新覆盖（宁可少量重复，不可漏报）。
- 整轮失败（认证过期等）→ 不推进水位线，按 [auth-errors](../auth-errors.md#常见错误处理) 处理后重跑。
