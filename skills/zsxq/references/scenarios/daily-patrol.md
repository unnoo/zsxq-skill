# 每日巡场（daily-patrol）

拉取星球最新 N 条主题，逐条读完整内容，按四类整理出星主今天需要处理的内容，并给出运营提醒。**纯只读场景：只分析、只报告，不做任何回复 / 加精 / 打标签 / 删除等写入。**

## 适用意图

- 「帮我看看『自我探索』今天有什么要处理的」
- 「查最新 20 条主题，按需要回复 / 适合加精 / 标签建议 / 需关注四类整理」
- 「每天早上巡场 / 巡检一下星球」
- 活动期间盯用户反馈；成员多、更新快时做快速筛选

## 不适用情况

- 只想按关键词找特定内容 → 用 [topic-search](../topic-search.md)，不必逐条拉全量
- 只想看自己跨星球发过什么 → 用 [user-footprints](../user-footprints.md)
- 已经选定某条主题、要直接回复 / 加精 / 打标签 / 删除 → 转对应写入操作（本场景只产出候选，不代替写入确认）
- 想按标签筛选主题 → 用 [group-hashtags](../group-hashtags.md)

## 所需输入

| 输入 | 必填 | 说明 |
|------|------|------|
| 星球（group_id 或星球名） | **是** | 只给名称时先用 `group +list` 解析出 group_id（见执行流程第 0 步） |
| 主题数量 N | 否 | 默认 20；`group +topics` 单页上限 30，超过需翻页（见分支条件） |
| 关注侧重 | 否 | 用户可指定只看某几类（如「只挑需要回复的」），未指定则输出全部四类 |

## 使用的原子操作

| 操作 | reference | 在本场景中的作用 |
|------|-----------|-----------------|
| `group +list` | [../group-list.md](../group-list.md) | 用户只给星球名时解析 group_id（第 0 步） |
| `group +topics` | [../group-topics.md](../group-topics.md) | 拉取最新 N 条主题作为待分析候选（含类型、时间、精华状态、互动计数） |
| `topic +detail` | [../topic-detail.md](../topic-detail.md) | 逐条拉取完整正文，供四类判定 |
| `get_topic_comments`（可选） | [../../SKILL.md](../../SKILL.md#主题管理topic) 的 API 表 | 当判定信号在评论里（q&a 是否已被回答、抱怨 / 求助 / 引战）时读取评论文本 |

> 前三个是主链路；`get_topic_comments` 仅在正文不足以判定 ①④ 类时按需调用，同为只读。

## 执行流程

### 第 0 步：确认 group_id（用户只给星球名时）

1. 运行 `group +list`，在结果里按名称匹配 group_id
2. 名称精确命中一个 → 直接用其 group_id
3. 命中多个相似星球 → 列出候选（group_id + 名称）让用户选，**不默认取第一个**
4. 一个都没命中 → 告知用户可能未加入该星球，让其核对名称或直接给 group_id

用户已直接给出 group_id 时跳过本步。

### 第 1 步：拉取候选主题

`group +topics --group-id <id> --limit <N>`（默认 20，最大 30）。用 `--json` 便于后续逐条取 topic_id、type、create_time、digested、counts。N > 30 时按分支条件翻页。

### 第 2 步：逐条拉取完整内容

对第 1 步每个 topic_id 调 `topic +detail --topic-id <id>`，取 `content`(正文)、`type`、`digested`、`counts`(comments/likes/readers)、`create_time`、`owner`。

- 正文能判定就用正文；判定 ①④ 需要评论证据时，对该条补调 `get_topic_comments` 读评论文本
- 每条之间轻微间隔，遇限流按分支条件退避

### 第 3 步：四类判定

逐条按下表归类。**一条主题可命中多类**（如既适合加精又建议打标签），分别列入；四类都不命中则不输出。

| 类别 | 命中信号（满足任一） | 排除 / 注意 |
|------|--------------------|------------|
| **① 需要我回复** | `type=q&a` 且尚无有效回答（comments=0，或评论里只有追问、无实质解答）；正文/评论有明确提问、求助、"求指导/怎么办/有没有人"；用户表达不满、抱怨、质疑 | 已由星主或他人充分回答的 q&a 不列入；判定"是否已答"需看评论，正文不含答案 |
| **② 适合加精华** | `digested=false` 且内容有深度：真实案例 / 复盘 / 实操经验 / 深度分析 / 高质量讨论；或互动显著高于同批（`counts.likes`/`comments`/`readers` 明显偏高） | `digested=true` 的已是精华，跳过；纯广告 / 灌水 / 打卡不算优质 |
| **③ 标签建议** | 内容明确属于某一类（如 工具推荐 / 复盘 / 读书笔记 / 提问 / 资源分享），适合归类打标签 | ⚠️ 主题现有标签**不以独立字段返回**，而是内联在正文的 `annotation`（URL 编码的 `<e type="hashtag">` 实体）里；本场景为轻量预览，只按内容给**建议标签**、不解析既有标签。可先跑 [group-hashtags](../group-hashtags.md) 看星球已有标签体系，让建议对齐现有标签、避免造重复标签 |
| **④ 需关注** | 负面情绪 / 情绪激动；引战、互相攻击、争议话题；敏感或可能违规内容（政治敏感、色情、诈骗、垃圾广告、外部导流、私留联系方式等） | 风险信号常在评论区，正文正常也要扫评论；本类只标记提醒，处置（删除等）由用户决定 |

> 判定是内容理解，不是关键词硬匹配：结合正文语义、`type`、`digested`、`counts` 与（必要时）评论综合判断。拿不准归类的，宁可列入 ①/④ 提示人工确认，也不要漏判。

### 第 4 步：按格式输出 + 运营提醒

四类各自成组，每条一行，统一格式：

```
主题标题 | 发布时间 | 处理建议
```

- 标题取 `title`；无标题时用正文首句/摘要，并标注（无标题）
- 发布时间取 `create_time`
- 处理建议一句话可执行（如"@提问者补一句解答""可加精，主题=真实复盘""建议打标签 #工具推荐#""疑似引战，先看评论再决定是否介入"）
- 某类无命中项，写"（今日无）"，不要省略该类

四类之后给 **1–3 条今日运营提醒**：综合当批整体情况（如"今天 3 条 q&a 待回复，优先处理""负面反馈集中在 X 活动，建议统一回应""优质内容偏少，可主动发起话题"），聚焦"今天该先做什么"。

## 分支与停止条件

- **无主题 / 今日无新内容**：`group +topics` 返回空或最新主题都早于用户关心的时间窗 → 报告"今日无新内容"，结束
- **星球名命中多个**：列候选让用户确认，不自选（见第 0 步）
- **N 超过单页上限（30）**：用上一页返回的 `next_end_time` 作为 `--end-time` 翻页续拉，直到凑够 N 或 `has_more=false`（翻页见 [group-topics](../group-topics.md#说明)）
- **限流（429 / frequently）**：退避几秒再重试该条，不要循环猛刷；持续受限则先输出已完成部分并说明剩余待续
- **个别 topic +detail 失败**：跳过该条、记录 topic_id，继续处理其余，最后在报告里列出未取到的条目
- **用户只要列表、不要分类**：退回到直接用 [group-topics](../group-topics.md)，不进入四类分析

## 用户确认点

本场景**全程只读**，产出的是"待处理候选 + 建议"，不含任何写入，因此执行分析阶段无需逐条确认。需要注意：

- 输出里的每条"处理建议"（回复 / 加精 / 打标签 / 删除等）都只是建议，**尚未执行**
- 用户选择对某条落地某个写入动作时，转到对应写入操作 reference，由那里的 `> [!CAUTION]` 块完成写入前确认——本场景不代为确认、不代为执行

## 完成标准

- 已拉取用户指定数量（或全部可得）的最新主题，并逐条取到完整内容（失败条目已在报告标注）
- 四类分别给出（含"（今日无）"），每条符合"标题 | 发布时间 | 处理建议"格式
- 已给出 1–3 条今日运营提醒
- 全程无任何写入操作

## 失败与回退

- 纯只读、无副作用，任意步骤中断都不会改动星球数据，可安全重跑
- 部分主题详情拉取失败：不影响已完成条目的分类；补齐时只需对失败的 topic_id 重跑第 2–3 步，无需从头再来
- group_id 取错（选错星球）：换正确 group_id 重跑第 1 步即可
