# 星球AI搜索总结（summarize-search-results）

用户已经在某个星球里搜索。按输入是一段话还是关键词，用 [topic-search](../topic-search.md) 取出主题，只根据正文打分，输出关联度最高的一批，并给出可点开的来源。**纯只读：不发帖、不评论、不写笔记、不改精华或标签。**

检索命令、参数和错误语义只以 [topic-search](../topic-search.md) 为准。沿用当前已选定的通道，不因输入类型改走另一条通道，也不调用 reference 未记载的接口。

- CLI 通道：`topic +search` 是增强检索，没有翻页参数。
- MCP 通道：`GET /v2/search/groups/{group_id}/topics`，只传 `keyword` 与 `count=20`。它是官方搜索，排序与 CLI 不同。

## 适用意图

- 「帮我总结这个星球里和 XX 相关的内容」
- 「搜不到，按相关度把最贴近的主题列出来」
- 「我想找某个同事之前发的项目，好像叫做花布」
- 同一搜索词下「继续看 / 换一批 / 再挖掘」

## 不适用情况

- 只想要搜索接口的原始列表、不要总结 → 直接用 [topic-search](../topic-search.md)
- 按时间浏览最新主题，没有搜索词 → 用 [group-topics](../group-topics.md)
- 已经指定某条主题，要看评论、发帖、加精或打标签 → 转对应原子操作
- 要搜索附件文件名 → 本场景不覆盖；[topic-search](../topic-search.md) 与文件搜索不是同一个接口

## 所需输入

| 输入 | 必填 | 说明 |
|------|------|------|
| 星球（group_id 或星球名） | 是 | 只给名称时先用 [group-list](../group-list.md) 解析。命中多个就列出候选，不默认取第一个 |
| 搜索内容 | 是 | 缺了只追问这一项，不搜索 |
| 继续挖掘 | 否 | 没有更换搜索词，只是继续看、换一批或不满意。不重新请求，用上一份已打分列表 |

不算星球名。搜索内容分成三类：

- 一段话：有句号、问号或感叹号，或是在陈述、提问一件事的完整句子。
- 多个关键词：用空格、逗号、顿号、加号或斜杠分开，读起来不是一句完整的话。
- 单个关键词：其余一个连续的词或短语。

## 使用的原子操作

| 操作 | reference | 在本场景中的作用 |
|------|-----------|-----------------|
| `group +list` | [../group-list.md](../group-list.md) | 只有星球名时解析 group_id |
| `topic +search` | [../topic-search.md](../topic-search.md) | 按当前通道检索主题。query / keyword 用用户输入，不拼星球名 |
| `topic +detail` | [../topic-detail.md](../topic-detail.md) | 检索结果只有标题或摘要、没有可打分正文时补拉正文 |
| 分享链接 | [../share-links.md](../share-links.md) | 「查看」用电脑端主题链接。不编造用户主页或其他链接 |

## 执行流程

### 第 0 步：确认 group_id

用户已给出 group_id 就跳过。只给星球名时按 [group-list](../group-list.md) 匹配；多个候选让用户选。

### 第 1 步：沿用或重新检索

- 没换搜索词，只是继续挖掘：不调用接口。跳过已展示的 `topic_id`，按第 4 步再输出最多 20 条。
- 换了搜索词、用户确认了某个候选词，或该词第一次总结：丢掉上一份打分。确认后的词按它自己是一段话还是关键词来打分。

调用 `topic +search`。`group_id`、`topic_id` 保持原样字符串，不要转成数字。

- CLI：`zsxq-cli topic +search --group-id <id> --query "<搜索内容>" --json`
- MCP：`{"method":"GET","path":"/v2/search/groups/<group_id>/topics","query":{"keyword":"<搜索内容>","count":20}}`

多个关键词保持用户原来的分隔。不传 `filter_roles`、`filter_types`，也不传 reference 里没有的翻页字段。

### 第 2 步：取正文并打分

检索条目里已有正文就直接打分。只有标题或摘要时，对该条调用 `topic +detail`。MCP 长文只有 `inline_article_url`、没有正文时，按 [topic-detail](../topic-detail.md) 说明跳过，不编造正文。

正文来源：CLI / 详情用 `content`；MCP 搜索命中用 `talk.text`，没有则用 `question.text` 与 `answer.text`。打分前清理：`<e>` 的 `href`、`title` 百分号解码后只取标题或标签；重复段落留一份；不描述图片和文件，不声称读过。

总分 100 的整数。只看清理后的正文和搜索词，不看点赞、评论、阅读、精华或接口顺序。

- 90–100：正文就是在讨论这件事。整篇在谈它时，即使没有逐字写出搜索词，也归这一档。
- 81–89：正文明确用该词讲了一件事，但不是整篇主题。
- 80 及以下：字形、读音或缩写接近，或没有实质讨论。只出现在链接或转发标题里，或只是清单、模板、会议名称里的一个字眼，也归这一档。

80 分不进入总结。一段话首页最低 81 分。关键词首页最低 90 分。

把搜索词、输入类型、通道、每条 `topic_id`、分数、`owner.name`、`owner.user_id`、`group_id`、摘要，以及已展示的 `topic_id` 留在对话里。

### 第 3 步：可能的正确词

只在关键词首页没有 90 分及以上，或一段话没有大于 80 分的主题时考虑。

候选必须是本次正文里连续出现过的实际用词，至少 2 个字；英文至少 2 个字母。不能编造，也不要按社区内容方向另猜。比较对象：关键词用用户输入；一段话不用整句，用句中要找的名称（「好像叫做花布」里的「花布」）。原词已连续出现时不给候选。不限只差一个字，只要这个词就是用户要找的名称。读音、字形或用词对得上即可，同音含同音节、声调不同。例如「奥云回」可推荐正文里的「奥运会」；「花布」推荐「星球数据画布」，不要拆成单字。多个关键词只替换对不上、且正文里有实际用词的那一段。

最多 3 个。更像目标名称的靠前；同样像的，出现条数多的靠前。不足 3 个不凑。

### 第 4 步：输出

用中文，不写分数。每句对得上该条正文。摘要不超过 50 个字，不含序号、用户名和「查看」。序号写成 `1. `。用户名用 `owner.name`，没有名字就不写。`z` 大于 20 时开头仍写实际数量，列表只留最高 20 条。

一段话没有合格主题：「主题正文里没有读到在讨论这件事。可补充一个记得的原话、作者或大概时间。」

关键词连 81 分都没有：「没有找到。试试用一段话描述下你要找的内容，或补充一个记得的原话、作者或大概时间...」

关键词仍有 81 到 89 分：「感觉结果不太对？试试用一段话描述下你要找的内容，或补充一个记得的原话、作者或大概时间...」

有候选词时，把候选接在说明后面，写成「可能是指 A、B、C」，不要做成链接。

有合格主题时：

```markdown
”xx“在本星球里找到 y 条内容，其中关联度最高的 top z 是：
1. {用户名}： {这一条在说什么} - [查看](https://wx.zsxq.com/group/{group_id}/topic/{topic_id})

如没找到你想要的，可尝试继续补充关键词，或去搜索结果里看看。
```

`xx` 是用户输入，`y` 是本次打分条数，`z` 是本页门槛以上的条数。`group_id` 用本次星球。继续挖掘且还有未展示主题时，不重复「找到 y 条」，序号接着排，底部仍用上面这句。关键词先展示未展示的 90 分及以上，再展示 81 到 89 分。

返回里没有高风险、用户删除、拉黑、限制搜索词的分类数量，不要汇总。见到 `intercepted_count` 也只当作无原因的合计数，不要把它说成上述任何一类。只有错误原文写明原因时才转述。

## 分支与停止条件

- **没有 group_id 或搜索内容**：只追问缺的那一项，不调用搜索
- **星球名命中多个**：列出候选，不自选
- **调用失败**：原样告诉用户错误信息后停止，见 [topic-search](../topic-search.md#错误说明) 与 [auth-errors](../auth-errors.md#常见错误处理)
- **检索为空**：不输出列表，按第 4 步的空结果文案，并按第 3 步决定是否给候选
- **结果已展示完**：写「相关主题已经展示完。可补充关键词，或去搜索结果里看看。」不重复已展示主题
- **要更多召回**：本命令没有翻页参数。不要补造 `index` 或其他查询字段。按 [topic-search](../topic-search.md) 换近义或相关词再检索，那是一次新的搜索词

## 用户确认点

本场景全程只读，检索和总结不需要逐条确认。

用户点名某个候选词，或在对话里确认其中一个之前，不要改搜索词，也不要为候选词再请求。一次只重搜被确认的那一个。

## 完成标准

- 已按输入类型选定门槛，并只展示达到门槛的主题
- 每条摘要不超过 50 个字，且能对上正文；「查看」是 [share-links](../share-links.md) 的电脑端主题链接
- 没有合格主题时使用对应空结果文案；有合格候选词时最多给出 3 个
- 继续挖掘没有重复请求，也没有重复已展示的 `topic_id`
- 全程无写入

## 失败与回退

- 纯只读，中断不会改动星球数据，可换对的 group_id 或搜索词重跑
- 个别 `topic +detail` 失败：跳过该条并记 `topic_id`，继续其余条目
- 官方搜索与 CLI 增强检索结果不同是通道差异，不是失败；不要为了补齐而混用通道
