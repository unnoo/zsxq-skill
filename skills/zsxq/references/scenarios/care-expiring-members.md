# 到期成员续费关怀（care-expiring-members）

识别星球里即将到期的成员，结合各人的活跃度与评论风格，分层生成续费关怀文案，方便星主做续费提醒与关怀跟进。**本场景只读取数据、生成文案草稿，不代替星主发送任何消息。**

## 适用意图

- 「查一下『[星球名]』里 14 天内即将到期的成员」
- 「帮我做到期成员的续费关怀 / 续费提醒」
- 「哪些成员快到期了，按活跃度给我分层写关怀话术」
- 活动或续费季前，识别高价值 / 沉默成员做针对性跟进

## 不适用情况

- 星球是**免费星球**，或当前账户**不是该星球的星主/管理员** → 拿不到 `expired_time`，本场景无法识别到期成员（见 [group-members](../group-members.md) 的可见性说明）
- 只想拉一次成员名单、不做续费分析 → 直接用 [group-members](../group-members.md) 原子操作
- 只想定位某一个具体成员 → 用 `search_group_members` 关键词搜索即可，不必走本场景
- 要真正群发续费消息 / 批量私信 → 本场景不覆盖发送，只产出文案草稿，由星主自行发送

## 所需输入

- **星球名称或 group_id**（必填）。只给名称时先用 [group-list](../group-list.md) 查到 group_id
- **到期时间窗口**（可选，默认「未来 14 天」）
- **成员数量上限**（可选，用于控制第二步逐人分析的规模）

## 使用的原子操作

| 操作 | reference | 在本场景中的作用 |
|------|-----------|------------------|
| `group +list` | [group-list](../group-list.md) | 由星球名称解析 group_id；确认当前账户是星主 |
| 成员列表（`api raw` GET members） | [group-members](../group-members.md) | 第一步拉取即将到期成员，翻页拉完 |
| `search_group_members`（`api call`） | 无独立 reference，见 [SKILL.md](../../SKILL.md) 星球管理 API 表 | 第二步在星球内按昵称定位成员、查看其发言 |
| `user +footprints` | [user-footprints](../user-footprints.md) | 第二步辅助判断成员活跃度（仅当目标是当前账户自身足迹时可用，见「分支与停止条件」） |
| 分享链接拼接 | [share-links](../share-links.md) | 输出中附上成员相关主题的可点击链接（可选） |

## 执行流程

### 第一步：拉取即将到期成员清单

1. 若用户只给了星球名称，先 `zsxq-cli group +list` 解析 group_id；名称命中多个相似星球时，列出候选（group_id + 名称）让用户确认，不要默认取第一个。
2. 确认当前账户是该付费星球的**星主/管理员**（否则 `expired_time` 不返回，直接转「不适用情况」）。
3. 按 [group-members](../group-members.md) 拉取普通成员，按到期时间正序、限定时间窗：

   ```bash
   zsxq-cli api raw --method GET --path /v2/groups/<group_id>/members \
     --query '{"scope":"regular","sort":"expired_time","order":"asc","begin_time":"<现在>","end_time":"<现在+14天>","count":200}'
   ```

   也可用 `scope=expired` 拉取已过期成员做补充。**成员多时按 [group-members](../group-members.md) 的翻页规则拉完全部**（时间排序用最后一条的 `expired_time` 推进 `begin_time`），不要只取第一页。
4. 整理成清单，计算「距今天数」（`expired_time` 减当前日期）：

   | 昵称 | 用户ID | 到期时间 | 距今天数 |
   |------|--------|----------|----------|

### 第二步：逐人分析活跃度与评论风格

对清单中每个成员：

1. 在该星球内按昵称搜索其发言：`zsxq-cli api call search_group_members --params '{"group_id":<id>,"keyword":"<昵称>","limit":10}'`，结合成员 `login_time`、发帖/评论记录判断。
2. 归纳三个维度：
   - **活跃等级**：高（每周有互动）/ 中（偶尔出现）/ 低（几乎无记录）
   - **评论风格**：主动分享型 / 提问求助型 / 点赞潜水型
   - **关注话题方向**：从其发言推断主要关注的内容方向
3. 汇总为分析表：

   | 昵称 | 到期时间 | 活跃等级 | 评论风格 | 关注话题方向 | 续费跟进建议 |
   |------|----------|----------|----------|--------------|--------------|

### 第三步：按活跃度分层生成关怀文案

依据第二步的活跃分层，各生成 **1 个** 100 字以内、口吻自然亲切的续费关怀话术模板：

- **高活跃成员**：强调社群价值、内容积累、已建立的连接
- **中活跃成员**：唤起记忆、突出近期有价值的内容
- **低活跃 / 潜水成员**：低压力提醒，不强推，给一个轻松的续费理由

文案是草稿产出，交给星主审阅后自行发送。

## 分支与停止条件

- **无权查看到期时间**（非星主/管理员，或免费星球）：`expired_time` 缺失 → 停止，说明原因并转「不适用情况」
- **窗口内无即将到期成员**：第一步返回空 → 报告「该窗口内无到期成员」，可建议放宽窗口或改用 `scope=expired` 查已过期成员
- **名称命中多个星球**：列出候选让用户确认后再继续
- **成员量大**：先反馈总数并与用户确认分析规模（如「先分析最先到期的前 N 人」），避免对上百人逐一搜索时触发限流
- **限流（429 / frequently）**：退避几秒重试，逐人分析之间适当放慢，不要循环猛刷
- **活跃度判断的局限**：`user +footprints` 只反映**当前登录账户自己**的跨星球足迹，不能拉取任意成员的完整发帖记录；成员活跃度只能借助 `search_group_members`、`login_time`、评论片段等信号**辅助推断**，不等同于该成员的完整发帖历史，结论需按此口径表述

## 用户确认点

- 本场景**无真实写入**：生成续费关怀文案属于内容产出，不是发帖/评论/私信，无需写入确认
- 但要**明确告知**：文案是草稿，实际发送由星主自行完成；本场景不会代发任何消息
- 逐人分析规模较大时，先与用户确认分析范围再批量执行

## 完成标准

- 产出「即将到期成员清单」（昵称 | 用户ID | 到期时间 | 距今天数），且已按翻页规则拉完目标窗口内全部成员
- 产出逐人「活跃度 / 评论风格 / 关注话题 / 跟进建议」分析表，并已声明活跃度判断为辅助推断、非完整发帖记录
- 产出高 / 中 / 低活跃三类各 1 个、100 字以内的续费关怀文案模板
- 全程未发送任何消息、未做任何写入操作

## 失败与回退

- 本场景全为只读 + 文案生成，无写入，**无需回滚**
- 第一步成功、第二步中途因限流或数据不足中断：已完成的清单和分析可直接交付，剩余成员标注「待补充」，恢复后续跑即可
- 判定拿不到 `expired_time`：停在第一步，向用户说明权限/星球类型限制，不强行往下走
