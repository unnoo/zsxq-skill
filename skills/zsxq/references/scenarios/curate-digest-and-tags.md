# 精华与标签整理（curate-digest-and-tags）

把星球里的优质内容沉淀成资产：查最近主题的标题与摘要做初筛，对候选拉完整内容判断是否值得加精、并结合现有标签给出标签建议，**先给确认清单、用户确认后才执行**加精与打标签。设精华、改标签都是写入操作。

## 适用意图

- 「帮我把「星球名」最近的主题整理一下，该加精的加精、该打标签的打标签」
- 「看看最近哪些帖子值得设为精华」
- 「把优质内容沉淀成星球资产 / 整理精华和标签」
- 星主想定期归拢优质内容与分类

## 不适用情况

- 已有一批明确的主题、只想批量打标签而不做加精判断 → [batch-tag-topics](batch-tag-topics.md)
- 只想看某个标签下有哪些主题 → [group-hashtags](../group-hashtags.md)（配合 `get_hashtag_topics`）
- 按关键词找特定内容 → [topic-search](../topic-search.md)
- 非星主账户：可产出建议清单，但加精/改标签的执行需要相应权限（见[完成标准](#完成标准)）

## 所需输入

- **星球名称或 `group_id`**（必填）：只给名称时先用 `group +list` 定位
- 检查的主题数量（可选，默认最近 20；单页上限 30，更多需翻页）
- 加精候选目标条数（可选，默认 5–8 条）
- 权限：设精华需**星主**；打标签需**主题作者或星主**

## 使用的原子操作

| 操作 | reference | 在本场景中的作用 |
|------|-----------|-----------------|
| `group +topics` | [../group-topics.md](../group-topics.md) | 拉最近 N 条主题的标题/摘要做初筛（`--json` 每条含 `digested`，可先剔除已精华项） |
| `topic +detail` | [../topic-detail.md](../topic-detail.md) | 对候选拉完整正文判断是否值得加精；打标签前读该主题**现有标签** |
| `group +hashtags` | [../group-hashtags.md](../group-hashtags.md) | 查星球现有标签清单，作为建议标签的词表，优先复用已有标签 |
| `set_topic_digested` | [../topic-digest.md](../topic-digest.md) | 写入：将主题设为精华（星主权限） |
| `set_topic_tags` | [../topic-tags.md](../topic-tags.md) | 写入：设置标签（`titles` 为完整标签集合，**覆盖而非追加**） |

## 执行流程

### 第一步：定位星球

只给星球名称时先 `group +list` 拿 `group_id`；名称命中多个相似星球时列出候选（`group_id` + 名称）让用户确认，不默认取第一个。

### 第二步：拉最近主题做初筛（只读）

`group +topics --group-id <id> --limit <N>`（默认 20），从标题/摘要初筛两类候选：

- **A 类（加精候选，默认 5–8 条）**：看起来有价值、值得沉淀的主题。用 `--json` 输出里的 `digested` 字段先剔除**已是精华**的，避免重复处理。
- **B 类（打标签候选）**：内容主题明确、适合归类的主题。

> 列表输出**不含标签信息**，因此 B 类此时只是「按标题/摘要的预判」；某条是否真的没打标签，要到第四步用 `topic +detail` 确认。

### 第三步：查现有标签（只读）

`group +hashtags --group-id <id>` 拉星球现有标签清单，作为建议标签的词表：**优先复用已有标签**，避免制造重复或近义的新标签。

### 第四步：拉详情、生成建议清单（只读）

- **A 类**逐条 `topic +detail`：读完整正文判断是否真的值得加精；同时再次确认 `digested` 现状。
- **需要打标签的主题**（A 类中需补标签的 + B 类）：`topic +detail` 读该主题**现有标签**（标签以内联形式出现在正文内容里，不是独立字段）。因为 `set_topic_tags` 是覆盖式，必须把要保留的旧标签一并并入建议的完整集合。
- 产出**确认清单**（表格）：主题标题 | `topic_id` | 建议操作（加精 / 打标签 / 两者） | 建议的完整标签集合 | 原因说明。

### 第五步：用户确认后执行（写入）

用户对清单确认后，逐条执行；命令与参数细节见各 reference：

- 加精 → `set_topic_digested`（`digested: true`），见 [topic-digest](../topic-digest.md)
- 打标签 → `set_topic_tags`（`titles` 传**完整标签集合**，含需保留的旧标签），见 [topic-tags](../topic-tags.md)

## 分支与停止条件

- `group +topics` 返回空 → 报告该星球暂无主题，结束
- 名称命中多个星球 → 列候选让用户选，不默认第一个
- A 类候选不足或超出 5–8 → 按实际数量给，不硬凑；数量过多时先请用户圈定范围或时间段
- 拉详情发现某 A 类主题**已是精华** → 从加精清单剔除并标注
- 预判的 B 类拉详情后发现**已有合理标签** → 从打标签清单剔除
- 当前账户非星主/无权限 → 见[完成标准](#完成标准)；执行时的权限错误见 [topic-digest](../topic-digest.md#错误说明) / [topic-tags](../topic-tags.md#错误说明)
- 限流（`429` / `frequently`）→ 退避几秒重试，不循环猛刷
- 用户只要建议清单、暂不执行 → 第四步结束

## 用户确认点

1. 星球定位有歧义时：确认目标 `group`
2. **任何写入前**：展示确认清单（标题 | 操作 | 完整标签集合 | 原因），逐条或批量取得用户明确同意
3. **打标签**特别确认：`titles` 是完整集合、会**覆盖**原标签，确认已并入需保留的旧标签（见 [topic-tags](../topic-tags.md) 的 `> [!CAUTION]`）
4. **加精**特别确认：设为精华会进入星球精华列表（见 [topic-digest](../topic-digest.md) 的 `> [!CAUTION]`）

## 完成标准

- 已确认的加精项 `digested` 均为 `true`；已确认的打标签项标签为约定的完整集合
- 未确认的主题保持原状
- 给出最终回执：哪些加了精、哪些改了标签、跳过了哪些及原因
- 非星主/无权限账户：产出建议清单即为本场景可交付部分，实际执行需由有权限的账户完成

## 失败与回退

- 加精与打标签**逐条独立、各自幂等**（见 [topic-digest](../topic-digest.md#失败语义) / [topic-tags](../topic-tags.md#失败语义)）：某条失败不影响其他条，无中间态
- 打标签失败重跑时仍传**完整集合**（覆盖式），不会叠加或重复
- 部分完成可续跑：仅对未成功的项重复第五步
