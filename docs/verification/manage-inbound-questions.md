## 实测校准了哪些文档假设

- **`get_self_answer_topics` 检测链路可用**：`topic_filter:"unanswered"` 返回当前账户名下所有星球的未答 q&a（本次 3 条全在猿圈），带 `group.{group_id,name}` 可定位来源星球、`content` 可起草答案、`create_time` 可排序。→ 场景"检测提问箱"步骤按文档工作。
- **检测是跨星球的**：返回的未答提问不限于某一星球（本账户在猿圈的 3 条被拉出），场景须按 group 分组呈现、并对"是否在可回答星球"做判断。

## 安全测试策略

- **策略**：检测（只读）已实测；回答（写入）因**不可逆 + 无安全测试载体**记为受限未执行。
- **为何不执行回答**：`topic +answer` 是**不可逆、每题仅一次**的写操作（回答后无法撤回、无法重答），不满足 net-zero 自复原前提；且当前账户的真实待答提问全在「猿圈」——**不在用户授权写入的 758421284 范围内**，跨账户/跨星球回答他人提问既超授权又不可逆。研发测试星球内没有"别人向我提问且我未答"的 q&a 载体可供无害验证。
- **不制造真实副作用**：严格不在猿圈回答（超授权），也不为了测试去伪造一个不可逆的回答。

## 未覆盖 / 已知风险

- **`topic +answer` 写路径未实测**（不可逆 + 无载体 + 超授权范围三重限制）。回填条件：在 **758421284 内**存在"他人向当前账户提出、且当前账户未答"的 q&a（需另一账户在该星球发起 q&a 提问），方可在授权范围内做一次真实回答验证；或产品提供 answer 的撤销/测试沙箱。
- "问题已回答"重复保护错误（topic-answer.md 特有错误）依赖先成功回答，同受限未测。
